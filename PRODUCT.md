# Product

## Register

product

## Users

HyperMail is for keyboard-first email power users who live in Gmail or Microsoft
mailboxes and need a faster desktop workflow than a browser inbox provides. The
primary user is an operator, founder, engineer, or solo professional triaging a
large working set while switching between sync state, thread context, AI help,
and reply actions.

Users often work under time pressure, with one hand on the keyboard, a large
mailbox cached locally, and intermittent connectivity treated as normal rather
than exceptional. They need the interface to keep trust: actions should feel
instant locally, queue state should be visible, and risky ambiguity should be
kept out of the path.

## Product Purpose

HyperMail is a keyboard-first, offline-first desktop email client for Windows.
It gives Gmail and Microsoft mail users a local-first triage surface with cached
threads, a resilient modifier queue, secure OAuth, command palette navigation,
AI-assisted summaries and drafts, and runtime visibility inside the app.

Success means the user can clear, classify, reply, snooze, archive, and inspect
mail without reaching for the mouse or wondering whether an action was lost.
The product should feel like an operational console for email: dense, calm,
fast, trustworthy, and explicit about local versus remote state.

## Brand Personality

Focused, dense, calm, operational.

The voice should be concise and tool-native. HyperMail should feel like a
serious desktop utility with enough craft to earn daily use, not like a splashy
consumer mail redesign. It can carry a quiet sense of progress, especially in
empty states and command surfaces, but its default posture is precision.

## Anti-references

- Generic SaaS hero UI with oversized marketing claims, decorative stat blocks,
  or productivity cliches.
- Decorative card-heavy layouts where every concept is isolated inside another
  framed box.
- Glassmorphism as a default aesthetic. Blur is allowed only where it supports
  shell depth or command focus.
- Noisy consumer-mail chrome, playful gradients, social feed patterns, or
  advertising-style visual hierarchy.
- Vague AI-assistant aesthetics where sparkles and purple glow replace clear
  workflow value.
- Hidden state. Queue, sync, offline, provider, and AI status must be visible
  when they affect user trust.

## Design Principles

- Keep the hands on the keyboard. Primary workflows should be reachable through
  shortcuts, command search, and dense controls before pointer-heavy UI.
- Show local truth first. Offline cache, queued actions, provider readiness, and
  sync state should be visible enough that users trust deferred work.
- Make density legible. The app should hold a large amount of information, but
  hierarchy, spacing, type weight, and status color must prevent visual mush.
- Treat AI as an operator aid. AI summaries, drafts, and split suggestions
  should appear as accountable tools with provider state and cached outcomes,
  not as a brand personality.
- Preserve desktop seriousness. Visual polish should reinforce reliability,
  speed, and focus rather than turning the product into a marketing surface.

## Accessibility & Inclusion

Target WCAG 2.1 AA for contrast, focus visibility, keyboard operation, and text
legibility. Keyboard access is a core product requirement, not an enhancement.
Interactive states must remain visible in high-density layouts, labels must not
depend on color alone, and motion should stay restrained with no bounce or
layout-shifting animation.
